# Коли от Америка — нов сайт

Next.js 16 + Payload CMS 3, TypeScript, SQLite и локално съхранение на изображения.

За тестово публикуване през Hostinger Web App вижте [HOSTINGER.md](docs/HOSTINGER.md). Налични са първоначална миграция на базата и `npm run hosting:prepare`; необходим е потвърден постоянен диск.

За визуално демо без постоянен диск: `PREVIEW_MODE=true`. Публичното съдържание се възстановява автоматично във временна база; формите за изпращане, API записите и админът са блокирани. Пълната версия с CRM остава зависима от постоянна база и файлове.

## Локално стартиране

Изисква Node.js 22.13+ (проверено с 24.19) и npm.

```sh
npm ci
npm run setup
npm run import:content
npm run dev
```

Сайтът е на порт 3000, администраторският панел е `/admin`. Създайте първия администратор през панела, преди да осигурите публичен достъп. Няма фабричен акаунт или парола. `.env` се създава с произволен локален ключ и не се записва в Git. Повторното `setup` не го презаписва.

`npm run import:content` добавя само липсващите страници от `content/wordpress.json`, оригиналните контакти и известните пренасочвания. Не презаписва редактирано съдържание. При първо стартиране CMS създава основни работни страници; след импорта съдържанието от WordPress е достъпно на оригиналните URL адреси.

## Админ панел

- **Автомобили**: собствени обяви, снимки, характеристики, цена в EUR, чернова/публикувано, SEO.
- **Страници и статии**: визуален редактор, начално описание, изображения, дата, SEO заглавие, описание и noindex.
- **Запитвания**: име, телефон, имейл, желан автомобил, бюджет, съобщение, статус и вътрешни бележки. Това е началният CRM.
- **Настройки на сайта**: контакти, Viber, Facebook, главно заглавие/снимка и въпроси/отговори.
- **Калкулатор за внос**: тарифни диапазони, коефициент на валутата и транспортни стойности.
- **SEO пренасочвания**: стар локален път → нов локален път. Пренасочванията са постоянни HTTP 308.

Собствените обяви `/avtomobili` са отделни от външните аукционни данни `/targove`. Запитванията се записват в CRM; изпращане на имейл и възстановяване на парола чрез имейл още нямат настроен доставчик. Payload в development използва стандартния си console email adapter.

## Търгове

Реализирани са филтри за марка, модел, година, състояние, гориво, продавач и аукцион, търсене по лот/VIN, странициране, детайли и галерия, запазване в браузъра и запитване за конкретен лот. Търсенето по VIN зависи от правата на доставчика; старият сайт също описва ограничение за тази функция.

**Директна интеграция:** предоставените плъгини са прегледани и е добавен ApiCar адаптер. Той се активира при наличен `APICAR_API_KEY`. Директният достъп е проверен с реалния защитен ключ: каталог, марки/модели, филтри и детайли за Copart и IAAI. VIN endpoint връща HTTP 403 и остава изключен. Вижте [API-INTEGRATION.md](docs/API-INTEGRATION.md).

**Временна зависимост без ключ:** `AUCTION_API_BASE_URL` по подразбиране е публичният `https://koliotamerika.bg/wp-json/koa/v1`. Новият интерфейс не използва WordPress, но този източник на търговете все още го използва. За завършване на премахването му е нужен API ключът и успешна live проверка на директния адаптер. Преди смяна на DNS тази връзка трябва да бъде преместена към независим backend; иначе ще сочи обратно към новия сайт и ще спре да работи.

Данните за търгове се кешират 60 секунди, списъкът с марки — 1 час. Показаните залози са в валутата на аукциона и **не са крайна цена за внос**. В сайта не се подават оферти и не се извършват покупки.

## Проверки

```sh
npm run typecheck
npm test
npm run test:e2e
npm run build
npm start
```

E2E проверките ползват отделна SQLite база и файлове в `/tmp`, отделна `.next-test` директория и порт 3100. Изискват Chromium на `/usr/bin/chromium`; пътят може да бъде зададен с `CHROMIUM_PATH`. Тестовият администратор има случайна парола и се създава само в тестовата база.

## Данни и публикуване

`.data/payload.db`, `public/media/` и `.env` са локални и изключени от Git. За продукция са необходими постоянен диск и резервни копия на базата и качените файлове. Тази конфигурация е за един Node сървър; не е подходяща за ephemeral/serverless файлови системи. За няколко инстанции планирайте PostgreSQL и S3 съхранение.

Преди публикация вижте [MIGRATION.md](docs/MIGRATION.md). `SITE_INDEXABLE=false` е умишлено: търсачките не трябва да индексират работния вариант. `NEXT_PUBLIC_SERVER_URL` трябва да бъде точният публичен HTTPS адрес при реалното стартиране.

При контролиран reverse proxy, който презаписва `X-Forwarded-For`, задайте `TRUST_PROXY=true` за индивидуално ограничаване на запитванията. Иначе ограничението е общо за инстанцията. За продукция добавете и ограничение на ниво proxy.
