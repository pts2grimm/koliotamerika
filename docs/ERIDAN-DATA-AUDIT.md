# Eridan: проверка на заявките и полетата — 13.10.2026

Проверени са текущият OpenAPI 2.0.0 на https://catalog.eridan.software/api/openapi.json, реални защитени GET заявки към API, подаденият от потребителя запис за лот 68880346 и [оригиналната обява на Copart за 57397516](https://www.copart.com/lot/57397516/salvage-2020-porsche-macan-s-nc-gastonia).

Прикаченият файл не можеше да се прочете поради нестартирала работна среда. Потребителят постави един пълен запис като текст; той е фиксиран в tests/fixtures/eridan-user-lot.json. Не е проверено съдържанието на останалите записи от прикачения файл. Пагинацията е проверена по реалния API и схемата.

## Установено разминаване за 57397516

Copart показва 14.10.2026, 07:00 PDT = 14:00 UTC = 17:00 Europe/Sofia.
Eridan върна два записа: sale_date 23.09.2026 и 02.09.2026, и двата със status not_sold и is_future_sale false. Първият е обновен на 13.10.2026, което не прави септемврийския търг актуален.
Заявката с lot_number, auction=copart и sale_date__gte към момента на проверката върна 0 резултата.
Следователно няма предоставена актуална дата за този лот в проверения API отговор. Не е приложена ръчна дата, фиксирано изместване на часовете или предположение за следващ ден.

## Поправки

- Каталогът подава документирания status=active за всеки поток и проверява статуса на върнатите записи. Предишната заявка допускаше исторически продажби.
- Детайлът и VIN/лот търсенето предпочитат активни участия. Историческите записи остават достъпни през запазени линкове, но не се представят като активни.
- Подреждането на точни обяви е по sale_date, а не updated_at. Последното е обновяване/внос на данни, не хронология на търговете.
- sale_date остава единственият източник на дата/час. is_future_sale не се използва за определяне дали датата е бъдеща: примерът на потребителя и реални предстоящи лотове имат false.
- Старо участие или изтекъл час в Eridan се показва като „Очаква се актуална дата“. В детайла старата дата е изрично обозначена като предишна; има връзка към оригиналния Copart лот.
- Историческите current_bid и buy_now_price не се представят като актуални цени.
- Версиите на кешовете за каталог/детайл/търсене са сменени, за да не се използват стари нормализирани записи.

## Полета от JSON

| Поле в Eridan | Обработка / предназначение |
| --- | --- |
| id | Вътрешен идентификатор на конкретния запис; използва се за подреждане/дедупликация на API страниците. Не е публичният номер на лота. |
| lot_number | Публичният lot_id; проверяват се цифри и безопасен числов диапазон. |
| auction | copart → site=1, iaai → site=2; самоличността е site:lot_number. |
| vin | Запазва се предоставената стойност, включително маскиран VIN. Точно VIN търсене изисква пълен валиден VIN. |
| name | Заглавие; при липса се сглобява от година, марка и модел. |
| make.name | Марка; не се печата целият вложен обект. |
| model.name | Модел; предпочита се пред series.name. |
| series.name | Резервен модел, когато model.name липсва; вътрешните IDs не се смесват. |
| year | Числова година. |
| item_type | VEHTYPE_V и VEHTYPE_M са допустими за каталога; VEHTYPE_R от примера е кемпер и се изключва. |
| color.name | Наличен в API, засега не се нормализира/показва. |
| trim | Наличен в API, засега няма отделно поле в страницата. |
| body_style | Наличен в API, засега не се нормализира/показва. |
| engine | Текстът се запазва без предположения за обем/единица. „10“ не се превръща в „10 литра“. |
| transmission | Запазва се текстът. |
| drive | Запазва се текстът. |

| has_keys | Наличен boolean, засега не се нормализира/показва. |
| highlights | Само разпознатите механични обозначения се превеждат: RUNS AND DRIVES, Engine Start Program, Stationary. CERT-D/S-STF5 не се тълкуват на предположение. |

| is_future_sale | Не е надежден заместител на сравнение между sale_date и текущото време. Не участва в брояча. |

| final_bid | Не се използва като текущ залог. |
| buyer_number | Не се показва и не се използва. |

## Заявки и пагинация

| Действие | Заявка |
| --- | --- |
| Каталог | GET /lots: auction=copart/iaai поотделно, status=active, item_type, has_images=true, ordering=-id, page/page_size. |
| Марка/модел/години | make__name, model__name, year_from, year_to; празните полета не се изпращат. |
| Допустими марки без избрана марка | makes като един CSV параметър, потвърдено с реални заявки; повтарящи се makes параметри използват само последния. |
| Гориво | fuel_type__name по реалните стойности от /fuel_types?auction=..., с обединяване на допустимите алиаси. |
| Точен лот | lot_number + auction + status=active, ordering=-sale_date. При реална липса на активен запис — заявка без status за историческа справка. При мрежова/API грешка не се подменя с история. |
| Точен VIN | vin + status=active, ordering=-sale_date, с проверка за точно съвпадение; след това история само при липса. |
| Марки | /makes с page/page_size/ordering=id, всички страници и проверка на count. |
| Модели | /models?make__name=... с page/page_size/ordering=id. |
| Категории | /item_types; стойностите и етикетите се проверяват. |
| Състояние/застраховател | Не се изпращат като механичен status или seller_type: такива филтри не са документирани. Това е различно от системния status=active. |
| Отговор от /lots | items, page, page_size, has_next; не се измисля total/count или брой крайни страници. |
| Отговор от директориите | items + count, пълна проверка за непълни/променени страници. |

Други документирани филтри (трансмисия, каросерия, пробег, изключване на щети и др.) още не са включени в интерфейса. Липсата им е функционално ограничение, не грешно четене на JSON.

## Ограничение, което остава при доставчика

Филтрирането на активни обяви и разграничаването на историята не създават липсващото активно участие на 57397516. Eridan трябва да предостави актуалния запис/дата. За проверката могат да се посочат публичният лот, auction=copart, двете получени септемврийски дати и датата 14.10 в Copart — без API ключ.
