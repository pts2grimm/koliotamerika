# API интеграция — преглед на предоставените KOA плъгини

Проверени файлове: `koa-auction-catalog`, `koa-auction-car-details`, `koa-catalog-search-filters`, `koa-popular-vehicles-slider`, `koa-facebook-share`, `koa-api-logger-v1.0.5`.

## Първи доставчик: ApiCar

Базов адрес: `https://api.apicar.store/api`. Автентикация: HTTP header `api-key`. Ключът се взема единствено от сървърната променлива `APICAR_API_KEY`. В ZIP файловете няма непразен вграден ключ; той е бил настройка в WordPress.

| Операция | Договор от плъгините | Нова реализация |
| --- | --- | --- |
| Каталог | `GET /cars`, отделен `site=1` или `site=2` | `createApiCarProvider.search` |
| Марки/модели | `GET /cars/makes-and-models` | `createApiCarProvider.makes` |
| Детайл | `GET /cars/{lot_id}?site=1|2` | `createApiCarProvider.detail` |
| Лот | Последователна проверка на детайла в Copart и IAAI | `createApiCarProvider.lookup` |
| VIN | `/cars/vin/all?vin=...`; изключено в предоставения код заради API плана | Изключено по подразбиране; `APICAR_VIN_ENABLED=true` само след потвърждение/проверка |
| Автоматичен bid refresh | `/cars/current-bid`; каталожният endpoint връща празен резултат в предоставения код | Не се стартира скрит polling; данните се кешират 60 секунди |
| Популярни автомобили | Първа страница на `/cars`, не реална класация | Актуални предложения на началната страница |
| Facebook | Шаблон за текст, цена до България, OG meta | Копиране на обява, Facebook споделяне, OG данни и CMS цени по лот |
| Запитвания | WordPress custom post type и имейл | CMS запитвания със статуси/бележки; имейл доставчик предстои |
| API лог | Заявки и статуси | Структуриран сървърен лог с `AUCTION_LOGGING=true`, без ключове, headers и body |

Коригирани особености при пренасянето: уникалният идентификатор включва аукцион и лот; страницирането при два аукциона се определя от максималния брой страници на отделния източник, не от общия брой резултати разделен на единичния page size. При HTTP 401/403 прекратяваме заявки към ApiCar за 30 минути; при 429 — за минута. Допълнителен бюджет: до 20 upstream заявки за минута на Node процес. Няма автоматични повторения на платени заявки при отказ за достъп. За няколко инстанции този бюджет трябва да бъде централизиран.

## Превключване

- Без `APICAR_API_KEY` се използва временният публичен WordPress мост.
- При наличен `APICAR_API_KEY` се избира директният доставчик.
- `AUCTION_PROVIDER=apicar` принуждава директен режим и връща контролирана грешка при липсващ ключ.
- `AUCTION_PROVIDER=legacy` позволява изричен временен fallback.
- Няма тих fallback от отказал директен API към WordPress.

Директният адаптер е проверен с contract тестове по предоставения PHP код и известните структури на данните. **Live проверка на 10 октомври 2026:** защитеният ключ е активен. Марки/модели: HTTP 200, 123 марки. Каталог и детайл: HTTP 200 за site=1 (Copart) и site=2 (IAAI), със снимки и съвпадащи лотове. Филтър по марка/модел: HTTP 200 с правилни резултати. VIN endpoint: HTTP 403 Forbidden, остава изключен. Реалният API изисква size >= 10; адаптерът вече прилага този минимум и има регресионен тест. Наличието на ключ автоматично избира директния адаптер; WordPress мостът остава само за среди без ключ.

## Втори доставчик

Предвиден е интерфейсът `AuctionProvider` със `search`, `makes`, `detail`, `lookup`. Не са измисляни endpoint-и или полета за втория API. След получаване на документацията трябва да се добавят отделен адаптер, идентификатор на доставчика в URL/запазените автомобили/цените, правила за обединяване и дедупликация, лимити и проверка на правата. До тогава `provider` в CMS цените е ограничен до `apicar`.

## Оставащ функционален преглед

В детайлния WordPress плъгин има допълнителни функции за сходни лотове, специални документни подсказки, видео/360 и алтернативен калкулатор. Нужни са сравнение на поведението и потвърждение кои са активни в бизнеса. Те не се считат за пренесени или live проверени само защото endpoint-ите са описани в стария код.
